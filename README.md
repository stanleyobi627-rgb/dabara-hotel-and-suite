# Dabara Hotel and Suites

Online booking website for **Dabara Hotel and Suites**, Ozubulu Road, Inyaba, Nnewi 435101, Anambra State, Nigeria.

Built with **plain HTML, CSS and JavaScript** — no framework, no build step, no backend. Serve the folder with any static web server and it runs.

## Highlights

- Live availability — units are counted against overlapping reservations in real time
- Four-step booking: stay details → guest details → payment → instant confirmation code
- Printable receipt, `.ics` calendar file and a one-tap WhatsApp message
- Guest self-service area to print, re-book, cancel or restore a reservation
- Staff dashboard: booking statuses, CSV export, full room catalogue editor, enquiries, hotel info
- **You control the prices** — edit rates, unit counts and room details in the dashboard, then publish the file
- Seven room types across **68 rooms**, priced in naira with 7.5% VAT
- Light and dark themes, fully responsive from 360px up, print stylesheet
- All artwork is original SVG generated by the project itself

## Running locally

The site uses ES modules, so it must be served over HTTP (opening `index.html` directly with `file://` will block the module imports).

```bash
npm run dev          # serves on http://localhost:5173
```

or with any static server:

```bash
npx serve .
python -m http.server 5173
```

### Checks

```bash
npm run check        # syntax check every browser JS file
npm test             # headless smoke test of the booking logic
npm run e2e          # end-to-end browser test (needs the site on :5173)
npm run probe        # console-error probe across every page
npm run art          # regenerate all SVG artwork
```

`BASE_URL` overrides the target for `e2e` and `probe`, so the same tests can be pointed at the live site:

```bash
BASE_URL=https://dabara-hotel-and-suite.vercel.app npm run e2e
```

## Booking logic

**Availability** — for each room type, every non-cancelled booking whose date range overlaps the requested stay reduces the number of units left. Adjacent stays (one ends the day the next begins) do not conflict. Availability is re-checked when the guest submits the booking, not just when the page loads.

**Pricing**

```
subtotal = nightly rate × nights × rooms
extras   = selected add-ons (extra bed charged per night, others per stay)
discount = promo code (percent or fixed)
vat      = 7.5% of (subtotal + extras − discount)
total    = subtotal + extras − discount + vat
```

**Confirmation** — every booking gets a reference like `DAB-KQM4821`, stored in the browser, and can be printed, exported to a calendar file, or sent over WhatsApp.

## Editing prices and rooms

You have two ways to change what guests see. Both end up in the same place.

### 1. From the dashboard (no code)

Open `admin.html`, sign in with the passcode, go to the **Rooms** tab. You can:

- change any rate, unit count, name, type, size, bed arrangement, occupancy, floor, view, rating, ribbon and description
- tick and untick the amenities included in each room
- upload a new room photo
- add a brand new room type or delete an existing one
- **Download rooms.json** — the catalogue as a JSON file
- **Copy js/catalogue.js** — the catalogue ready to paste over `js/catalogue.js`
- **Upload rooms.json** — load a catalogue back in

Dashboard changes are saved in the browser and apply to the whole site immediately, because every page reads the catalogue through `js/rooms-store.js`. They do **not** change the file on the server — for that, use the download or copy button and publish the result.

### 2. By editing the file (permanent)

Open `js/catalogue.js` and change the numbers. One array, one room per object:

```js
export const ROOMS = [
  {
    id: "standard",          // used in links — do not change once published
    name: "Standard Room",
    type: "Standard Room",
    rate: 38000,             // price per night
    units: 18,               // how many of this room the hotel has
    size: 24,                // m²
    beds: "1 Queen bed",
    maxGuests: 2,
    floor: 2,
    view: "Courtyard view",
    rating: 4.2,
    reviews: 52,
    tag: "Best value",       // ribbon on the card
    amenities: ["wifi", "ac", "tv", "bath", "power", "keycard"],
    image: "images/room-standard.svg",
    description: "Shown on the room card and booking page.",
  },
];
```

Then commit and publish. The room type filter, the total room count in the hero and the occupancy report all read from this one file, so they can never disagree with it.

## Deployment

The site is fully static, so any static host works.

**Live site:** <https://dabara-hotel-and-suite.vercel.app>

**Vercel**

```bash
npx vercel          # preview
npx vercel --prod   # production
```

`vercel.json` enables clean URLs, adds security headers and sets cache rules for the artwork.

The Vercel project (`great-innovators/dabara-hotel-and-suite`) is connected to the GitHub repository, so every push to `main` deploys automatically — no build command, output directory is the repository root.

**GitHub Pages / Netlify / Cloudflare Pages**

Push the repository and point the host at the repository root — there is no build command and the output directory is the repository root.

## Notes and limitations

- **No backend.** Everything lives in the visitor's browser via `localStorage`. Bookings made on one device are not visible to the hotel, and clearing browser data removes them. A real deployment needs a server, a database and a payment processor.
- **The payment form is a demonstration only.** No card is validated, tokenised or charged.
- **The admin passcode is stored in a public file.** `js/data.js` is served to every visitor, so the passcode is a convenience, not security. Real staff access needs server-side authentication.
- **Dashboard edits are per-browser.** They apply immediately across the site in that browser, but for every guest, publish `js/catalogue.js`.
- **Room photos uploaded in the dashboard** are stored as data URLs in the browser only.
- **The email address is a demo address.** Replace `HOTEL.email` in `js/data.js` with the hotel's real inbox before launch. The phone number, address and check-in times are the hotel's real details.
- **Google Maps** is linked rather than embedded, so no API key or third-party request is needed.
